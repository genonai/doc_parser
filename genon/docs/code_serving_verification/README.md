# 코드서빙 배포 검증 핸즈온 — 동시 요청(#481·#482)

develop 의 변경을 코드서빙 배포본으로 빌드해 GenOS 코드서빙 리비전으로 올리고, 클라이언트에서 동시 요청을 보내
요청 간 간섭 없이 처리되는지를 확인하는 절차다. 로컬 단위 테스트가 "고친 자리가 고쳐졌다" 를 보장한다면, 이 절차는
"배포본이 실제 동시 요청에서 안전하다" 를 보장한다. 둘은 대체 관계가 아니다.

이 문서는 묶음(장)으로 나뉘어 있고 앞 묶음의 결과를 보고 다음 묶음을 진행한다.

| 묶음 | 문서 | 하는 일 | 걸리는 시간 |
|---|---|---|---|
| 1 | [01_build.md](01_build.md) | doc_parser 소스에서 배포본(doc_parser_code_serving)을 조립해 테스트 브랜치로 push | 5분 |
| 2 | 02_revision.md (묶음 1 결과 후 작성) | 기존 코드서빙에 대조군·수정본 리비전을 만들고 기동 확인 | 10분 + 기동 대기 |
| 3 | 03_concurrency_test.md (묶음 2 결과 후 작성) | 코드스페이스에서 동시 요청 클라이언트 실행, 결과·로그 비교 | 실행 20~30분 |

## 전제

- 코드서빙이 이미 한 번 배포되어 동작 중인 사이트. base 이미지 등록과 코드서빙 생성은 끝나 있다(`build-script/code-serving-README.md` 1·2번).
- 코드서빙은 GitHub 의 `genonai/doc_parser_code_serving` 을 외부 저장소로 직접 연결한다. 리비전은 브랜치와 커밋 해시로 고정된다.
- 설정(프로세서 yaml, `model_presets.yaml`)은 저장소가 아니라 사이트 NFS 의 리소스 폴더에 두고 환경변수 `GENOS_RESOURCE_DIR` 로 가리킨다. 배포본 저장소는 공개이므로 서빙 ID·API 키를 커밋하지 않는다.
- 클라이언트는 같은 클러스터의 코드스페이스에서 코드서빙 서비스에 직접 호출한다. 게이트웨이 인증키가 필요 없다.

## 사이트 값

코드서빙 번호, NFS 리소스 폴더 경로, 모델 서빙 주소와 키 같은 사이트 값은 이 문서에 적지 않는다. 문서의
`<CODE_SERVING_ID>`, `<NFS_RESOURCE_DIR>` 같은 자리표시자를 진행 중 전달받은 값으로 바꿔 읽는다.

## 대조군을 2.2.4 가 아니라 develop 으로 잡는 이유

릴리스 2.2.4 는 enrichment 토글을 enrichment 직전에 적용해 공유 인스턴스가 덮이는 창이 수 마이크로초다.
develop 은 잡 시작 시점에 적용해 파싱이 끝날 때까지(수 분) 창이 열려 있다. #481 이 고치는 것은 후자이므로,
"수정 전" 은 2.2.4 배포본이 아니라 develop 최신 커밋의 배포본이어야 한다.
