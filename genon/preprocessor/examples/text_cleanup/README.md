# 청크 텍스트 정제 — 사용 예시 3종

RAG 검색을 방해하는 문자 노이즈를 청크 본문에서 걷어내는 방법이 두 가지 있고, 둘을 섞을 수도
있다. 세 가지를 같은 원천으로 실제로 돌려 산출을 대조하는 예시다.

```bash
./run_cleanup_examples.sh              # 3종 전부
./run_cleanup_examples.sh --only yaml  # yaml 만
```

| 예시 | 정제하는 자리 | 쓰는 때 |
|---|---|---|
| `yaml` | `chunking_processor_config.yaml` 의 `chunking.text_cleanup` | 전 문서 공통. 코드 변경 없음 |
| `post_chunk` | `chunking_processor.py` 의 `post_chunk` 훅 | 특정 doc_type 만. 설정으로 못 가릴 때 |
| `both` | 위 둘을 함께 | 공통은 설정, 그 doc_type 의 예외만 훅 |

## 어느 것을 골라야 하는가

**기본은 `yaml` 이다.** 규칙이 **청킹 입력**에 걸리므로 삭제가 청크 경계와 `n_char` 에
반영되고, LLM 보강이 보는 텍스트까지 같이 깨끗해진다. 코드를 고치지 않는다.

`post_chunk` 는 **doc_type 별로 다르게 정제해야 할 때만** 쓴다. `text_cleanup` 은 프로세서
전체에 걸리는 설정이라 doc_type 을 가릴 수 없다. 대신 대가가 있다.

- 청크 경계는 이미 정해진 뒤라, 지운 만큼 청크가 작아지고 다시 합쳐지지 않는다.
- 파생 필드가 옛 값으로 남는다. **`toolbox.refresh_stats(vectors)` 를 반드시 부른다** —
  안 부르면 `n_char` 가 실제 길이와 어긋난다(실측: 11건 중 9건).
- LLM 보강은 정제 전 텍스트를 봤다.

## 지우면 안 되는 것

원천(`.INC_235488_02_20260626103138.html.parsed`)에는 `<`, `>` 가 261쌍 있지만 **청크에는
1개만 남는다** — docling 이 표로 바꿔 준다. 그래서 원문을 보고 규칙을 정하면 과잉이 된다.
청크 산출을 보고 정해야 한다. 그 파일의 청크(11건 / 2,582자)에 실제로 남는 특수문자 225개 중

- 지울 것: `■`5 `◈`4 `※`3 `☎`1, 미해독 엔티티 `&gt;`3
- 남길 것: `|`66(마크다운 표의 칸 경계), `.`32 `,`31 `(`9 `)`9 `:`8 `-`10(문장부호),
  `[`·`]`12(파이프라인이 붙인 `[표 검색 설명]`·`[AI 에이전트용]` 라벨), `~`2(기간 표기)

`|` 를 지우면 표 11건이 전부 뭉개진다. "특수문자를 다 지운다"는 이 원천에 대해서는 오답이다.

## 실측 (`./run_cleanup_examples.sh`)

| 예시 | 청크 | 총자수 | 장식마커 | 엔티티 | n_char 불일치 |
|---|---|---|---|---|---|
| baseline | 11 | 2,671 | 13 | 0 | 0 |
| yaml | 11 | 2,661 | 0 | 0 | 0 |
| post_chunk | 11 | 2,514 | 0 | 0 | 0 |
| both | 9 | 2,337 | 0 | 0 | 0 |

**기준선의 엔티티가 0 인 것에 주의하세요.** 예전에는 `&gt;` 가 청크까지 그대로 왔는데,
마크다운 백엔드가 본문과 표 셀에서 엔티티를 해독하도록 고쳐(#363) 원천에서 해결됐습니다.
그래서 정제 규칙에는 엔티티 항목이 없습니다 — 우회 규칙을 남기면 진짜 수정을 가립니다.

`both` 가 9건인 것은 훅이 내부용 안내 청크 2건을 버렸기 때문입니다.

**총자수의 절대값은 실행마다 움직입니다** — cs_hpp 는 표 설명을 LLM 이 생성하므로 그 문장이
매번 같지 않습니다. 그래서 이 예시의 단정은 절대값이 아니라 "정제 후 장식마커·엔티티가 0"
과 "n_char 불일치 0" 입니다.

두 방식이 **어디에** 걸리는지는 다릅니다. 설정 규칙은 청킹 입력에 걸려 표 셀과 LLM 보강
프롬프트까지 정제되고 `mode: safe` 의 줄 정리가 함께 적용됩니다. `post_chunk` 는 완성된
청크 본문에서 마커만 빼므로 그 두 이점이 없습니다.
